Carino PACS is a self-hosted DICOM gateway and continuity appliance. It receives studies, routes and forwards them, answers Query/Retrieve and DICOMweb, and can serve the worklist itself while your PACS is unreachable. One config file, one process, no cloud.

  • Linux: easiest is the .rpm (Fedora/RHEL) or .deb (Debian/Ubuntu) from the releases. The .AppImage needs FUSE — sudo dnf install fuse-libs (Fedora) / sudo apt install libfuse2 (Debian), or run it with --appimage-extract-and-run.

What it is

  • A gateway between your equipment and your archive. Studies arrive, get routed by rules you write, and are retried until every destination has taken them.
  • A continuity appliance. When the primary PACS stops answering, it serves the worklist itself, holds what arrives, and back-fills once the primary returns.
  • A translator for equipment nothing else will talk to. Print-only modalities, consoles with no RIS feed, readers that speak nothing but DIMSE.
  • Yours, on your hardware. One config file, one process, no cloud, no telemetry, no licence server. AGPL-3.0.

What it is not

  • Not a medical device. It is not certified, cleared or registered anywhere, and nothing in it has been validated for clinical use by anyone. Whoever deploys it owns that validation.
  • Not for primary diagnosis. There is no diagnostic viewer here: no windowing, no measurements, no rendering pipeline. Read studies on the validated workstation you already have.
  • Not an enterprise archive. No high availability, no clustering, no retention policies, and no encryption at rest — put it on an encrypted disk. It has its own profiles and audit trail, but no LDAP, no Active Directory and no single sign-on, so accounts live on the appliance rather than with your identity provider.
  • Not a replacement for your PACS or your RIS. It is the gateway between them, and the thing that keeps a department working through an outage until they come back.

If a patient's care depends on it, the responsibility for that is yours, not this software's.

What it does

Every service is off until you turn it on. The tag on each card is the release it ships in.

📥 Receive and filev1.0

A Storage SCP that accepts C-STORE and C-ECHO and files each study to disk by patient, study and series. Compressed objects are stored exactly as they arrived — never transcoded.

📤 Route and forwardv1.0 · rules v1.1

Forwards to as many nodes as you like, with rules: CT from the ER to the archive, ultrasound to the reading room. Each destination is retried until it accepts. A file that matches no rule goes everywhere rather than nowhere.

🕶️ De-identify on the way outv1.1

A rule can de-identify the copy it sends (PS3.15 Basic profile) while the archived original stays untouched. It does not clean burned-in pixel text — a human still has to look at the images.

🔎 Query/Retrievev1.1

C-FIND, C-MOVE and C-GET over an indexed view of what is actually on disk, so a twelve-year-old ultrasound or CR reader can ask what you hold and pull it back.

🌐 DICOMwebv1.1

QIDO-RS, WADO-RS and STOW-RS, so OHIF, Weasis and other modern viewers can read the archive over HTTP without negotiating a DICOM association.

📋 Worklist and emergency RISv1.1

Takes HL7 orders over MLLP or hand-keyed ones, and serves them to modalities as a Modality Worklist. If your primary PACS stops answering, it can take over, hold what arrives, and forward it once the primary is back.

🖨️ Virtual printv1.1

Captures print-only modalities as PDF, so a machine whose only output is film still produces something you can file.

🔑 Token authenticationv1.1

The dashboard and the DICOMweb API take a single shared token. Bind them to anything other than localhost without one and the server refuses to start — the refusal is the feature.

👥 People and permissionsv1.1

Optional per-person sign-in with four editable presets. Permissions are checked at every endpoint, not hidden in the browser, and you choose per profile which patient identifiers each person may see — so IT can trace a study by accession number without reading anyone's chart.

🔒 Audit trailv1.1

Append-only, hash-chained records of who did what, to which study, from where, and whether it worked — refusals included. Any edit or deletion inside the file breaks the chain and the dashboard says which record and why.

Running it on a server

🐳 Docker

git clone https://github.com/MiguelCarino/Carino-PACS
cd Carino-PACS
mkdir -p data && sudo chown -R $(id -u):$(id -g) data
docker compose up -d
docker compose logs -f pacs

The first boot prints an access token. Open http://127.0.0.1:8042/ and paste it when the dashboard asks. Everything — config, studies, logs, index — lives in ./data.

🐧 Linux service (systemd)

git clone https://github.com/MiguelCarino/Carino-PACS
cd Carino-PACS
sudo packaging/systemd/install.sh

The installer sets everything up and then stops: starting a PACS opens listeners that accept patient data, so that stays your decision. Edit /var/lib/carino-pacs/config.json, then systemctl start carino-pacs.

For technical users — DICOM details, CLI & source

Built on pynetdicom/pydicom with a Flask dashboard; the desktop app is an Electron tray shell around the same engine.

  • Storage SCP — C-STORE + C-ECHO, files by Patient/Study/Series, all transfer syntaxes (compressed stored as-is), allowed_aets filtering.
  • Storage SCU — folder-watch auto-forward to N nodes, conditional routing rules, per-destination retry, keep/move/delete on success.
  • Query/Retrieve SCP — C-FIND / C-MOVE / C-GET, Patient and Study Root, answered from a sqlite index of what is on disk; failed sub-operations are named, never dropped.
  • DICOMweb — QIDO-RS, WADO-RS, STOW-RS under /dicom-web, exact-match CORS allow-list, no wildcard. Rendered/thumbnail/transcoding answer 406 rather than fake it.
  • MWL + HL7 — Modality Worklist C-FIND SCP, HL7 ORM^O01 over MLLP, accession-number reconciliation. Image delivery is never gated on an order match.
  • De-identification — PS3.15 Annex E Basic profile on forward, with the retain options declared in (0012,0064). Pixels are not touched.
  • DICOM-TLS both sides (optional), incl. mutual TLS. Bearer-token auth on the HTTP API; non-loopback web.host with an empty token is a startup error.
  • Web dashboard, headless CLI (pacs serve|receive|send|echo|ris|mwl|qr), tray app, Docker image, or systemd unit. DICOM port 11112; dashboard 127.0.0.1:8042.
