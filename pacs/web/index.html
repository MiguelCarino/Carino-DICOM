    Query and web access
    Query/Retrieve (Q/R SCP)

    Answers C-FIND, C-MOVE and C-GET out of the instance index, so keep the index on. A C-MOVE opens a NEW association to the receiving node and calls out with the Q/R AE title above, not the auto-send one — a node that filters on calling AE title must allow it, or every C-MOVE is rejected. C-MOVE destinations are resolved from qr.move_destinations in the config file.

    DICOMweb

    Paste the base URL into a web viewer as its DICOMweb root. It answers out of the instance index, so keep the index on. Every request needs the API token when one is set; a browser viewer on another origin also has to be listed above.

    Privacy and security
    De-identification

    ⚠ Burned-in annotation is NOT removed. Text drawn into the pixels — ultrasound and screen-capture images especially — still carries the patient's name after any profile here.

    A profile only applies where a routing rule asks for it, so nothing is scrubbed until a rule with de-identify on sends to a node. With the profile off such a rule never sends an identified copy: that destination is held instead — the studies wait in the outgoing folder, nothing is deleted, and every other destination still gets them. Turn a profile on, or take de-identify off the rule, to release them.

    Write the key down somewhere safe before you set it. Replacing it later re-pseudonymises everything exported from then on, so old and new exports stop lining up.

    API access

    Copy the new token somewhere safe first. It takes effect the moment you apply it, signs out every browser including this one, and the dashboard can never show it again.

    Changing the token needs the current one typed in — a session cookie is not enough to replace the secret that issued it.

    A token is mandatory whenever the dashboard is bound to anything other than this machine, so removing it is refused while that is the case. It is stored in web.auth_token in the config file.
