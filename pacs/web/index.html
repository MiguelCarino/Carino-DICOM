New files in the watched folder are forwarded to every enabled node, retried until each accepts. Tick TLS to connect to a node over DICOM-TLS — the client cert/CA come from the Auto-send settings.

rules · which node gets what

Rules are read top to bottom. A rule with no destination is a filter and falls through; a rule whose destinations are all missing or disabled falls through too. If nothing matches, the study goes to every enabled destination — a study is never sent nowhere. The one exception: while the de-identification profile is off, a destination a rule asks to de-identify for is held rather than sent identified.

No rules yet — every study goes to every enabled destination.

Modality Worklist (MWL)

Point a modality at this AE / port as its Modality Worklist source. It pulls every open order (from 📋 Orders) by C-FIND; set an order's Target modality AE to steer it to one station. The order's Study UID is burned into the exam, so the returned study reconciles exactly.

Emergency RIS

Point a RIS (or an HL7 test sender) at this host:port over MLLP to feed ORM^O01 orders, or hand-key them in 📋 Orders. Tell the tech to type the Accession # into the modality — that's what matches the study back to its order. Image delivery is never blocked by a missing match.

Query/Retrieve (Q/R SCP)

Answers C-FIND, C-MOVE and C-GET out of the instance index, so keep the index on. A C-MOVE opens a NEW association to the receiving node and calls out with the Q/R AE title (CARINOQR), not the auto-send one — a node that filters on calling AE title must allow it, or every C-MOVE is rejected. C-MOVE destinations are resolved from qr.move_destinations in the config file.

De-identification

⚠ Burned-in annotation is NOT removed. Text drawn into the pixels — ultrasound and screen-capture images especially — still carries the patient's name after any profile here.

A profile only applies where a routing rule asks for it, so nothing is scrubbed until a rule with de-identify on sends to a node. With the profile off such a rule never sends an identified copy: that destination is held instead — the studies wait in the outgoing folder, nothing is deleted, and every other destination still gets them. Turn a profile on, or take de-identify off the rule, to release them.

API access

Copy the new token somewhere safe first. It takes effect the moment you apply it, signs out every browser including this one, and the dashboard can never show it again.

Changing the token needs the current one typed in — a session cookie is not enough to replace the secret that issued it.

A token is mandatory whenever the dashboard is bound to anything other than this machine, so removing it is refused while that is the case. It is stored in web.auth_token in the config file.
